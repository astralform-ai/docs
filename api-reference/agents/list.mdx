---
title: "List Agents"
api: "GET /v1/agents"
description: "Get the agent an API key belongs to."
---

Returns the agent this API key belongs to, as a one-element array. Its `name` is the only value `agent_name` accepts when [creating a job](/api-reference/chat/stream), and since the key already identifies the agent, you can leave `agent_name` out.

## Authentication

<ParamField header="Authorization" type="string" required>
  The agent's API key as a bearer token: `Bearer sk_xxxxxxxxxxxx`
</ParamField>

## Response

A JSON array of agent objects.

<ResponseField name="agent" type="object">
  One entry of the array.
  <Expandable title="Agent object">
    <ResponseField name="id" type="string" required>
      The agent's id
    </ResponseField>
    <ResponseField name="name" type="string" required>
      Agent identifier (lowercase with hyphens) — this is what `agent_name` takes
    </ResponseField>
    <ResponseField name="display_name" type="string | null" required>
      Human-readable name, or `null`
    </ResponseField>
    <ResponseField name="avatar_url" type="string | null">
      The agent's avatar, or `null`
    </ResponseField>
    <ResponseField name="code_projects_enabled" type="boolean">
      Whether this agent's tasks can name a repository — derived from an enabled `github` connector whose workspace holds an installation. Clients read it to decide whether to offer Projects and Tasks.
    </ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl -X GET https://api.astralform.ai/v1/agents \
  -H "Authorization: Bearer sk_xxxxxxxxxxxx"
```
</RequestExample>

<ResponseExample>
```json 200
[
  {
    "id": "3f9a1c72-5b84-4e10-a6d3-0c17e2b95f48",
    "name": "support-agent",
    "display_name": "Customer Support",
    "avatar_url": null,
    "code_projects_enabled": false
  }
]
```

```json 401
{
  "detail": "Invalid or missing API key"
}
```
</ResponseExample>

## Usage Notes

<Note>
  The response always carries **one entry**: an agent is a workspace, and an API key belongs to exactly one. There is no multi-agent routing to discover.
</Note>

- Sending `agent_name` in [Stream a Chat](/api-reference/chat/stream) is optional. If you send it, it must be this agent's `name`; any other name returns `404`.
