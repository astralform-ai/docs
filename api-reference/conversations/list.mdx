---
title: "List Conversations"
description: "Retrieve a paginated list of conversations for the authenticated project."
api: "GET /v1/conversations"
---

## Endpoint

```
GET https://api.astralform.ai/v1/conversations
```

## Request

### Headers

```
X-API-Key: af_live_xxxxxxxxxxxx
```

### Query Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `limit` | integer | 20 | Number of results (1-100) |
| `offset` | integer | 0 | Pagination offset |
| `order` | string | "desc" | Sort order: "asc" or "desc" |

## Response

```json
{
  "data": [
    {
      "id": "conv_abc123",
      "created_at": "2024-01-15T10:30:00Z",
      "updated_at": "2024-01-15T10:35:00Z",
      "message_count": 5
    },
    {
      "id": "conv_def456",
      "created_at": "2024-01-14T09:00:00Z",
      "updated_at": "2024-01-14T09:15:00Z",
      "message_count": 12
    }
  ],
  "meta": {
    "total": 42,
    "limit": 20,
    "offset": 0
  }
}
```

### Conversation Object

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique conversation identifier |
| `created_at` | string | ISO 8601 creation timestamp |
| `updated_at` | string | ISO 8601 last update timestamp |
| `message_count` | integer | Number of messages in conversation |

## Example

### cURL

```bash
curl -X GET "https://api.astralform.ai/v1/conversations?limit=10" \
  -H "X-API-Key: af_live_xxxxxxxxxxxx"
```

### Swift

```swift
let conversations = try await client.listConversations(
    limit: 10,
    offset: 0
)

for conv in conversations {
    print("\(conv.id): \(conv.messageCount) messages")
}
```

## Pagination

Use `limit` and `offset` for pagination:

```bash
# First page
GET /v1/conversations?limit=20&offset=0

# Second page
GET /v1/conversations?limit=20&offset=20

# Third page
GET /v1/conversations?limit=20&offset=40
```

The `meta.total` field indicates the total number of conversations.

## Caching

The list is per-user and changes whenever a conversation is created, renamed, or deleted, so it is **validated rather than cached**:

```
Cache-Control: private, no-cache
ETag: "a37f16fa0c7d3fda…"
```

`no-cache` does not mean "do not store" — it means the response may be stored but must be revalidated with the server before every reuse. Send the `ETag` back as `If-None-Match` and you get a bodiless **304 Not Modified** when nothing has changed:

```bash
curl -X GET "https://api.astralform.ai/v1/conversations?limit=20" \
  -H "X-API-Key: af_live_xxxxxxxxxxxx" \
  -H 'If-None-Match: "a37f16fa0c7d3fda…"'
```

The validator is derived from the response body, not from timestamps — [renaming a conversation](/api-reference/conversations/rename) deliberately leaves `updated_at` untouched, so a timestamp-based validator would report "unchanged" for a title the user just edited.

<Note>
  Browsers revalidate on their own. Application code needs the header explicitly: `ETag` is exposed via `Access-Control-Expose-Headers` and `If-None-Match` is allowed cross-origin, so a browser-based client can read and send it.
</Note>
