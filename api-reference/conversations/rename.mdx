---
title: "Rename Conversation"
description: "Replace the title the server generated from a conversation's first turn."
api: "PATCH /v1/conversations/:id"
---

## Endpoint

```
PATCH https://api.astralform.ai/v1/conversations/{conversation_id}
```

The server names a conversation once, from its first turn. This endpoint is the only way that label changes afterwards.

## Request

### Headers

```
X-API-Key: af_live_xxxxxxxxxxxx
Content-Type: application/json
```

### Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `conversation_id` | string | The conversation to rename |

### Body

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | The new title. Trimmed before validation, then 1–200 characters. |

```json
{
  "title": "Q3 earnings review"
}
```

## Response

**200 OK**

```json
{
  "id": "conv_abc123",
  "title": "Q3 earnings review",
  "message_count": 16,
  "created_at": "2024-01-15T10:30:00Z",
  "updated_at": "2024-01-15T10:35:00Z"
}
```

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique conversation identifier |
| `title` | string | The stored title, after trimming |
| `message_count` | integer | Number of messages in the conversation |
| `created_at` | string | ISO 8601 creation timestamp |
| `updated_at` | string | ISO 8601 last-activity timestamp — **unchanged by a rename** |

## Renaming does not reorder your history

`updated_at` is deliberately left alone. Conversations list newest-updated first, so stamping it would move a months-old conversation to the top of the list the moment you relabelled it. A rename is not activity.

Merge the returned row rather than stamping your own timestamp, or you reintroduce the reordering the API avoids.

## Example

### cURL

```bash
curl -X PATCH https://api.astralform.ai/v1/conversations/conv_abc123 \
  -H "X-API-Key: af_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"title": "Q3 earnings review"}'
```

### JavaScript

```javascript
// @astralform/js >= 4.7.0
await session.renameConversation("conv_abc123", "Q3 earnings review");
```

The SDK writes server-first: if the server rejects the title, nothing changes locally and the call rejects.

## Error Responses

**422 Unprocessable Content** — the title is blank after trimming, or longer than 200 characters.

```json
{
  "detail": [
    {
      "loc": ["body", "title"],
      "msg": "String should have at least 1 character",
      "type": "string_too_short"
    }
  ]
}
```

**403 Forbidden**
```json
{
  "detail": "Access denied"
}
```

**404 Not Found**
```json
{
  "detail": "Conversation not found"
}
```

**401 Unauthorized**
```json
{
  "detail": "Invalid or expired token"
}
```

## Notes

<Note>
  A title made only of whitespace is rejected rather than stored. A blank title would render as a placeholder derived from the conversation ID, silently discarding the name.
</Note>

Renaming requires the same access as deleting: you can only rename a conversation you own, on an agent you own or administer.
