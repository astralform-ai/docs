## Overview

Check whether the agent can take a chat turn before starting one. An agent is ready once its team has connected at least one [model provider](/dashboard/llm-providers). The model itself is not part of the status: it is chosen per turn or by the agent's conversation model, and the models on offer come from `GET /v1/models`. iOS clients should call this on app launch to show appropriate UI when no provider is connected.

Ready means a turn can start, not that every turn will succeed. A request that names no model, in a new conversation, on an agent with no conversation model still returns `400` — send `provider` and `model`, or set the agent's [conversation model](/dashboard/llm-providers#choose-the-model).

When the credential's agent doesn't exist, the response has `is_ready` and `llm_configured` both `false`, the message `No agent configured.`, and empty `capabilities`.

## Response

<ResponseField name="is_ready" type="boolean">
  Whether the agent is ready for chat.
</ResponseField>

<ResponseField name="llm_configured" type="boolean">
  Whether the agent's team has connected at least one model provider.
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable status: `Agent is ready for chat.`, `No model provider connected. Connect one in the dashboard.`, or `No agent configured.`
</ResponseField>

<ResponseField name="ui_components" type="object">
  Which UI protocol, if any, the agent may emit through `render_surface` / `update_surface`: `enabled` (boolean), `protocol` (string or `null`) and `mime_type` (string or `null`). The client picks a matching renderer.
</ResponseField>

<ResponseField name="capabilities" type="array">
  What the agent can do right now, so a client offers a feature only where it will work. Each entry is `{ "key": string, "enabled": boolean }`; keys are `image`, `video`, `web`, `skills` and `voice`. Empty whenever `is_ready` is false. `voice` is on when the developer enabled [voice input](/dashboard/voice) — the signal to show a microphone; [`/v1/voice/config`](/api-reference/voice/config) then carries the defaults. It tracks the developer's switch, not channel readiness: a speech-to-text key removed after the switch was turned on leaves `voice` on while every recording answers **409 `voice_not_ready`**, which a client handles by telling the user voice input is not available for this agent.
</ResponseField>

<ResponseExample>
```json Ready
{
  "is_ready": true,
  "llm_configured": true,
  "message": "Agent is ready for chat.",
  "ui_components": { "enabled": false, "protocol": null, "mime_type": null },
  "capabilities": [
    { "key": "image", "enabled": false },
    { "key": "skills", "enabled": true },
    { "key": "video", "enabled": false },
    { "key": "voice", "enabled": true },
    { "key": "web", "enabled": true }
  ]
}
```

```json No Provider Connected
{
  "is_ready": false,
  "llm_configured": false,
  "message": "No model provider connected. Connect one in the dashboard.",
  "ui_components": { "enabled": false, "protocol": null, "mime_type": null },
  "capabilities": []
}
```
</ResponseExample>

## Example

<CodeGroup>
```swift Swift
let status = try await client.getAgentStatus()

if !status.isReady {
    // Show setup required UI
    showConfigurationRequired()
}
```

```bash cURL
curl https://api.astralform.ai/v1/agent/status \
  -H "Authorization: Bearer sk_xxxxxxxxxxxx"
```
</CodeGroup>
