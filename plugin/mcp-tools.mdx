## Overview

The Astralform connector exposes the MCP tools below, which Claude can use to manage your Astralform projects. They are invoked automatically when you ask Claude to perform Astralform operations, on any surface where you've [added the connector](/plugin/connect).

A **project** here is what the dashboard calls an **agent**: the workspace, and the one agent that runs in it. Most tools take its id as `agent_id`.

## Authentication

Authentication is automatic via OAuth — Claude handles it when you add the connector and first use any tool.

| Tool | Description |
|------|-------------|
| `astralform_whoami` | Get current developer profile |
| `astralform_get_stats` | Get aggregate account statistics |

## Teams

| Tool | Description |
|------|-------------|
| `astralform_list_teams` | List all teams you belong to |
| `astralform_get_team` | Get team details by ID |
| `astralform_create_team` | Create a new team with name and slug |
| `astralform_list_team_members` | List members and their roles in a team |

### Example: List Teams

```
Show me my Astralform teams
```

Claude will call `astralform_list_teams` and display your teams with roles.

## Projects

| Tool | Description |
|------|-------------|
| `astralform_list_projects` | List the projects in a team (requires `team_id`). Members see the ones they created; team owners and admins see all. |
| `astralform_get_project` | Get project details by ID (includes team_id) |
| `astralform_create_project` | Create a new project under a team (requires `team_id`) |
| `astralform_update_project` | Update project name |
| `astralform_delete_project` | Delete a project |

### Example: Create Project

```
Create a new Astralform project called "My AI Assistant" under my startup team
```

Claude will select the team, call `astralform_create_project` with the `team_id`, and return the project ID and encryption key.

## LLM Configuration

These tools manage the agent's **conversation model** — the model it uses when a request doesn't name one.

| Tool | Description |
|------|-------------|
| `astralform_list_llm_providers` | List the model providers Astralform supports, with each one's catalog models |
| `astralform_get_llm_config` | Get the agent's conversation model, and whether its provider key is connected |
| `astralform_set_llm_config` | Set the agent's conversation model (provider + model, optional reasoning effort and temperature) |
| `astralform_delete_llm_config` | Clear the conversation model |

<Note>
  Provider API keys are held **per team**, in the Model Providers vault — not per agent. Connect the key with [`astralform_set_provider_key`](#provider-keys) *before* setting a model; `astralform_set_llm_config` refuses a provider whose key isn't connected, rather than saving a model that would fail at request time.
</Note>

### Example: Configure LLM

```
Store my Anthropic key, then set claude-sonnet-5 as my agent's model
```

Claude will call `astralform_set_provider_key` first, then `astralform_set_llm_config` with the provider and model.

Clearing the model leaves the agent with no default: every request must then name a model explicitly, or the run fails.

## Search Settings

| Tool | Description |
|------|-------------|
| `astralform_get_search_settings` | Get web search configuration |
| `astralform_set_search_settings` | Turn web search on or off (`is_enabled`), and choose its provider: `ddgs` (free, no API key), `tavily`, `serper` or `exa`. `max_results` is 1–10; `deep_research` sets the research tool's budgets. |

### Example: Enable Search

```
Enable web search for my project
```

Claude will call `astralform_set_search_settings`. The default provider, `ddgs`, needs no API key; the others take one.

## Memory Settings

| Tool | Description |
|------|-------------|
| `astralform_get_memory_settings` | Get memory configuration |
| `astralform_set_memory_settings` | Configure retrieval, extraction and limits (`retrieval_limit` is 1–20 memories per turn), or point the agent's end-user memory at an external provider |
| `astralform_test_memory_settings` | Probe the agent's memory provider, or a proposed provider and key before you save them |

Memory is always on; `is_enabled` is accepted but ignored. Pointing an agent's end-user memory at an external provider needs a team owner or admin, and `egress_acknowledged: true` to confirm what leaves Astralform — see [Memory Providers](/dashboard/memory-providers).

### Example: Recall More Memories

```
Have my agent recall up to 10 memories per turn
```

## Memory

Your own long-term memories on an agent, as the agent sees them in your conversations. These are scoped to you, the signed-in developer, never another user.

| Tool | Description |
|------|-------------|
| `astralform_memory_search` | Search your memories on an agent, ranked by relevance |
| `astralform_memory_add` | Save a memory for the agent to recall in your later conversations |
| `astralform_memory_list` | Browse your memories on an agent, newest first, plus facts shared at the agent and team scope |

### Example: Save a Memory

```
Remember on my support agent that I prefer answers in British English
```

## Agents

A project holds exactly one agent. To create or delete an agent, create or delete the project with the [Projects](#projects) tools.

| Tool | Description |
|------|-------------|
| `astralform_list_agents` | List the project's agent (always one) |
| `astralform_get_agent` | Get the agent's name, display name, system prompt and autonomy mode |
| `astralform_update_agent` | Update the agent's name, display name, system prompt or autonomy mode |

### Example: Update an Agent

```
Make my support agent supervised, so it asks before running tools
```

Claude will call `astralform_update_agent` with `autonomy_mode: "supervised"`.

## Provider Keys

Provider keys belong to a team and are shared by every agent on it.

| Tool | Description |
|------|-------------|
| `astralform_list_provider_keys` | List your default team's stored provider keys (hints only) |
| `astralform_set_provider_key` | Store a key for a provider. Requires the owner or admin role; `team_id` picks the team (default: your default team). Custom endpoints and Azure OpenAI also need `custom_base_url`. |
| `astralform_delete_provider_key` | Remove a stored key. Requires the owner or admin role, and is refused while routines depend on the provider. Takes `team_id` like set, and `confirmed: true` to answer a guard that asks for confirmation. |
| `astralform_test_provider_key` | Test your default team's stored key with a tiny request |

### Example: Store Provider Key

```
Save my OpenAI API key sk-xxx for Astralform
```

Claude will call `astralform_set_provider_key` to securely store the key.
