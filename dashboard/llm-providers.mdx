## Overview

Astralform runs every model on **your own provider key**. A team owner or admin connects each provider once, on the team's **Model providers** page. The key is encrypted and stored for the whole team, not per agent, and it is never shown again: the page only displays a hint of it. Every agent in the team can then use the models of any connected provider.

Which model a turn runs on is a separate decision, made where the turn starts: an agent has no model of its own. See [Choose the model](#choose-the-model).

## Providers

| Provider | Needs | Models |
|----------|-------|--------|
| **Anthropic**, **OpenAI**, **Google AI Studio**, **xAI (Grok)**, **Mistral AI**, **DeepSeek**, **Cohere**, **Groq**, **Together AI**, **OpenRouter**, **NVIDIA**, **MiniMax**, **Moonshot AI**, **Moonshot Coding**, **Z.AI**, **Z.AI Coding Plan**, **Ollama Cloud** | API key | Astralform's curated catalog |
| **Fireworks AI** | API key | Models you [register](#registering-models) |
| **Azure OpenAI** | API key and your resource's endpoint URL | Deployments you [register](#registering-models) |
| **Self-hosted endpoint**: any OpenAI-compatible server, such as llama.cpp, vLLM, Ollama or a proxy | Base URL, API key and a name | Models you [discover or register](#registering-models) |

Astralform maintains the catalog by hand and changes it as providers ship and retire models, so this page does not list them. The model picker in the dashboard is the current list, and API clients read the same list from [`GET /v1/models`](#for-api-clients).

<Note>
  **Ollama Cloud** is Ollama's hosted service and needs an Ollama API key. To use an Ollama server you run yourself, add it as a [self-hosted endpoint](#self-hosted-endpoints).
</Note>

## Connect a provider

Only team **owners and admins** see the Model providers page.

1. Open the account menu at the bottom of the sidebar → **Model providers**.
2. Under **Available**, find the provider and click **Configure**.
3. Paste the **API Key**. Azure OpenAI also needs a **Base URL**: your resource's endpoint.
4. Pick a **Chat model** and click **Test**. Astralform sends that model a short prompt with your key and reports whether it answered. Fireworks AI and Azure OpenAI have no catalog, so type the model name instead (for Azure OpenAI, the deployment name), and [register it](#registering-models) after saving so agents can pick it.
5. Click **Save**. The provider moves to **Configured**.

The key is write-only. To replace it, open **Configure** again and type the new key; **Save** stays disabled until you do. **Delete Key** removes it, except while routines, or reminders that haven't fired yet, use the provider: the dashboard refuses and names them.

### Self-hosted endpoints

1. On **Model providers**, click **Add endpoint** under **Self-hosted endpoints**.
2. Enter the server's **Base URL**, its **API key** and a **Name**. The name becomes the endpoint's identifier (`custom:<slug>`) and can't be changed afterwards.
3. Save it, then add its models as described in [Registering models](#registering-models).

<Warning>
  The base URL must be a public `http` or `https` address. Astralform connects to it from its own servers and refuses anything that resolves to a private or loopback address, such as `localhost`, `127.0.0.1` or `192.168.x.x`, so a server that only listens on your own machine can't be connected directly. Put it behind a public URL first.
</Warning>

### Registering models

Fireworks AI, Azure OpenAI and self-hosted endpoints have no catalog, so you tell Astralform which models to offer. Open the provider's **Configure** dialog and use **Team models**:

- **Discover models** (self-hosted endpoints) asks the server what it serves. It reads the `/models` list, then LiteLLM's `/model/info` or llama.cpp's `/props` for details, and lets you pick which models to add.
- Otherwise, add a model by hand. Enter its **Model** name (for Azure OpenAI, the deployment name), its **Context window**, whether it reasons (**Thinking**), and whether it supports **Tools** and **Vision**, then click **Register**.

The context window is required. Astralform budgets every conversation against it, and a model without one can't be used. Registered models only appear in pickers while the team holds a key for their provider.

## Choose the model

An agent has no default model. Each surface that runs an agent names the model it runs on:

| Surface | Where the model is set |
|---------|------------------------|
| **Chat and the API** | The chat's model picker, or `provider` and `model` on [`POST /v1/jobs`](/api-reference/chat/stream). A conversation's first message must name one; later messages reuse it unless they name another. |
| **Routines and reminders** | The routine or reminder editor. A routine without a model doesn't run. |
| **[Telegram](/dashboard/telegram) and [GitHub](/dashboard/github)** | The **Model** card on the connector's page. The bot doesn't answer until it has a model, and a change applies from the next message. |
| **Curated knowledge** | The model picker on the **Knowledge** page's **Curated** card, chosen for each ingest. A retry reuses the ingest's model. |
| **Memory consolidation** | The model of the job whose completion triggered it. A scheduled or manual run uses the end user's most recent job's model, and skips merging when there isn't one. |
| **Goals** | A goal started with `/goal` in Telegram runs on the channel's model. Any other goal continues on its conversation's model. |

Where a surface offers a model picker, it has the same three fields:

| Field | What it sets |
|-------|--------------|
| **Model** | The provider and model. Only providers the team has connected appear. |
| **Reasoning effort** | How hard the model reasons. See [Reasoning effort](#reasoning-effort). |
| **Temperature** | 0–2. Leave it empty for the provider's default. Some models don't accept a temperature, and on those it is ignored. |

### How a turn picks its model

Each chat or API turn resolves its model in this order:

1. **The request.** `provider` and `model` on [`POST /v1/jobs`](/api-reference/chat/stream), always supplied together. An explicit choice wins, even partway through a conversation.
2. **The conversation.** The model the conversation's previous turn used. A `reasoning_effort` or `temperature` sent with this turn still applies.

A new conversation has no previous turn, so its first message must name its model. One that doesn't is refused with `400` before the conversation is created: `A new conversation must name its model: pass provider and model. Later messages in the conversation may omit them and reuse its model.`

## Reasoning effort

Models differ in how much control they give over reasoning, so each model advertises its own **ladder**, some subset of **Off**, **Minimal**, **Low**, **Medium**, **High**, **Extra high** and **Max**. The picker offers **Model default** plus the rungs of the selected model, and a model with no ladder shows no effort control at all.

- **Model default** sends no effort, and the provider decides.
- **Off** is an explicit request not to reason, sent as `reasoning_effort: "none"`. It is not the same as the default, because many models reason unless told otherwise.
- A saved effort that the selected model doesn't offer (after switching to a different model, for example) is never sent as-is. The turn runs at the model's default instead.

## Speech-to-text from the same key

A **Groq** or **OpenAI** key also serves speech-to-text, and so can a self-hosted endpoint. Voice input is set up per agent; see [Voice](/dashboard/voice).

## For API clients

- **`GET /v1/models`** lists the models of every provider your team has connected, registered models included. Each entry carries `provider`, `model`, `context_window`, `tools`, `vision` and `thinking_control`, which holds the model's effort ladder and its default. Build a model picker from it.
- **`POST /v1/jobs`** accepts `provider`, `model`, `reasoning_effort` and `temperature` for each turn. See [Stream chat](/api-reference/chat/stream).
- **[`GET /v1/agent/status`](/api-reference/status/agent)** reports `is_ready: false` until the team has connected at least one provider.
- From Claude Code, the [Astralform plugin](/plugin/mcp-tools#provider-keys) can connect provider keys and set a Telegram or GitHub connector's model.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `A new conversation must name its model…` | Send `provider` and `model` with the conversation's first message. |
| Telegram or GitHub replies `No model is set for this … connector yet` | Pick a model on the connector's page, under **Model**. |
| Telegram or GitHub replies `…its provider isn't connected` | Reconnect that provider's key, or pick another model on the connector's page. |
| **Test** says `Connection failed. Check your API key and try again.` | The key is wrong or revoked, or it has no access to the selected model. |
| `No known context window for model '…'` | The request named a model Astralform has no context window for, typically an unregistered model on a self-hosted endpoint. [Register](#registering-models) it with its context window, or choose a catalog model. |
| `URL points to private or internal address` | The base URL resolves to a private or loopback address. Use a public URL. |
| `Cannot delete: routines or reminders use this provider: …` | Move those routines and reminders to another provider's model first, then delete the key. |
