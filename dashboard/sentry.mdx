## Overview

Sentry is a **remote MCP connector**: the agent's tools come from Sentry's hosted MCP server, and each team member connects their own Sentry account through Sentry's OAuth. Nothing is pasted and no token is stored by hand. A debugging agent can search unresolved issues, read an issue with its latest event, cross-reference the code through the [GitHub connector](/dashboard/github), and update the issue once the fix ships.

## 1. Enable the connector

1. Go to **Project Settings → Connectors** and enable **Sentry**. There is nothing to enter.
2. Choose the agent access policy (see [Access](#access)).

## 2. Connect your account

1. Open the Sentry connector and click **Connect**.
2. A Sentry consent screen opens in a popup. Pick the organization and the permissions the agent may use: **Inspect Issues & Events** (on by default) covers the read tools, **Triage Issues** lets agents resolve, assign and archive issues, and **Seer** enables the root-cause analysis tool. **Manage Projects & Teams** is not needed for debugging — leave it off unless agents should create projects, teams or DSNs.
3. The popup closes on its own and the connector shows your connection.

Each member connects individually; an agent uses the connection of the member who is chatting with it. Connections refresh themselves and can be revoked from the same card.

<Note>
  Routines, goals and reminders run under no member, so on their own they have no Sentry connection. A member can lend theirs: turn on **Use my connection for routines and goals** on the connector page and the agent's headless runs act on that member's Sentry account (one fallback per connector; disconnecting withdraws it). The connector page names whose connection routines use.
</Note>

## Agent tools

The tools are **discovered from Sentry's server** the first time an agent runs for a connected member (not on Connect itself), cached for an hour, and listed on the connector page from then on. They carry the `sentry_` prefix, so the connector's access policy governs all of them. Sentry's current server offers, among others:

| Tool | Purpose |
|------|---------|
| `sentry_find_organizations`, `sentry_find_projects` | Discover the slugs the other tools take. |
| `sentry_search_issues` | Search issues with Sentry's search syntax. |
| `sentry_search_events` | Search events and errors, including natural-language queries. |
| `sentry_get_sentry_resource` | Read one issue, event or trace in detail. |
| `sentry_update_issue` | Resolve, reopen, archive or assign an issue. |
| `sentry_analyze_issue_with_seer` | Ask Sentry's Seer for a root-cause analysis. |

The write tools (`sentry_update_issue`, `sentry_analyze_issue_with_seer`, and `sentry_execute_sentry_tool`, the executor that reaches the rest of Sentry's tool catalog) are governed as writes by the agent's [Autonomy](/dashboard/permissions) setting: a **Supervised** agent shows an approval card before running one in chat, and fails the call outright in a headless routine. The exact list is whatever the server lists; check the connector page once an agent has run for a connected member.

## Access

Sentry uses the standard connector [access policy](/dashboard/connectors#access-policy) — **Auto-allow** (recommended), **Ask user**, or **Block** — set in the connector's own settings. Disabling the connector removes the tools immediately.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| The popup never returns | Check the browser did not block it; the card offers a click-through link while it waits. |
| A tool answers "the Sentry connection was rejected — reconnect it in the dashboard" | Your grant expired or was revoked on Sentry's side. Click **Reconnect**. |
| "Tools are discovered from the server the first time an agent runs for a connected member" and no list appears | No agent has run for a connected member yet, or the last discovery failed; start a conversation with the agent and reload. |
| "Failed to complete authorization" after consenting | Sentry's authorization server refused the exchange. Try **Connect** again — the connector re-registers with Sentry if needed. |
