## Overview

An agent doesn't choose a sandbox template: the tool it calls does. Code tools run in the **Code** environment, and desktop tools run in the **Desktop** environment. There is nothing to configure per agent.

| Environment | Image | Started by |
|-------------|-------|------------|
| **Code** | `code-interpreter-v1` | `capsule_run_code` and the other code tools |
| **Desktop** | `desktop` | The `desktop_*` computer-use tools |

A run can hold one sandbox of each kind at the same time.

## Code

A Jupyter-powered sandbox with stateful code execution and rich output:

- 2 vCPU, 4 GB RAM, about 6.9 GB of free disk
- pandas, numpy, matplotlib, scikit-learn and 30+ other data-science packages
- `ffmpeg`, `deno`, `gh`, `rclone` and `yt-dlp`
- faster-whisper `base` weights, so the agent can transcribe audio offline

## Desktop

A full Ubuntu desktop with VNC streaming, Chrome, Firefox and VS Code. The agent drives it through screenshot, mouse and keyboard tools, for GUI interaction, visual verification and computer use.

<Note>
  The `base` and `browser` system images from earlier versions are retired. No agent is given one.
</Note>

## Custom templates

Custom template builds have been retired. **Capsule** → **Templates** now lists the two environments above, read-only. A custom build never completed, and no agent could have run on one: the sandbox environment is always chosen by the tool, and a build from a plain base image lacks the Jupyter server the code tools need and the desktop stack the desktop tools need.
