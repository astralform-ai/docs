## Overview

An agent is the workspace you open in the dashboard, and the thing that runs. Its instructions, skills, connectors, memory, sandbox and permissions all belong to it. Agents are independent of each other: there is no main agent, no routing between agents, and no supervisor. To give a different job a different setup, create another agent.

Switch agents with the **agent switcher** at the top of the sidebar.

Agents belong to a [team](/dashboard/teams). Model provider keys are the one team-wide setting, on [Model Providers](/dashboard/llm-providers); everything else on this page is per agent.

## Creating an agent

1. Open the agent switcher at the top of the sidebar → **New agent**.
2. Enter an **Agent name**: lowercase letters and numbers, separated by single hyphens, such as `support-bot`. It must be unique in the team.
3. Create the agent, then save the **encryption key** it shows you. It is displayed only once.

You land on the new agent's **Instructions** page, where you set its display name, avatar and system instructions.

Any team member can create an agent, and its creator owns it. Team owners and admins see and manage every agent in the team; members see the agents they created.

## What an agent configures

Everything lives in the agent's sidebar:

| Group | Page | What it sets |
|-------|------|--------------|
| **Build** | **Instructions** | Name, display name, avatar, and the agent's system instructions |
| | **Routines** | Scheduled runs |
| | **Tasks** | Long-running goals and their live status |
| | **Skills** | Installed skills, and recommended ones to install. See [Skills](/dashboard/skills). |
| | **Connectors** | The external services the agent can use. See [Connectors](/dashboard/connectors). |
| | **Search**, **Images**, **Video** | The web search, image generation and [video generation](/dashboard/video-generation) providers. See [Platform Tools](/dashboard/platform-tools) for search. |
| | **Voice** | Voice input. See [Voice](/dashboard/voice). |
| **Intelligence** | **Memory** | What the agent remembers, where, and what it learns. See [Memory Providers](/dashboard/memory-providers). |
| | **Knowledge** | Documents the agent can search |
| **Capsule** | **Pods**, **Templates**, **Settings** | The agent's sandboxes and their network access. See [Pods](/dashboard/capsule/pods). |
| **Observe** | **Analytics**, **Audit Log** | Usage, and a record of changes |
| **Settings** | **Permissions** | Whether the agent runs tools on its own or asks first, and tool rules. See [Permissions](/dashboard/permissions). |
| | **Environment** | Environment variables and secrets |
| | **API Keys** | Keys your app uses to call this agent. See [API Keys](/dashboard/api-keys). |
| | **Agent settings** | The conversation model, streaming thresholds, conversation titles, and deleting the agent |

### Conversation model

The model an agent uses when a request doesn't name one is its **conversation model**, set under **Settings** → **Agent settings** → **Conversation model**:

| Field | What it sets |
|-------|--------------|
| **Model** | Provider and model. **None (resolved at run time)** leaves the agent without a default, so a new conversation must name its model in the request. |
| **Reasoning effort** | How hard the model reasons, from the rungs that model offers. **Model default** leaves it to the provider. |
| **Temperature** | 0–2. Empty uses the provider's default. |

Only providers the team has connected appear here. See [Model Providers](/dashboard/llm-providers) for connecting providers and for how a turn picks its model.

### Sandbox

Every agent can run code in an isolated Capsule sandbox, with nothing to switch on. A sandbox starts the first time a run calls a code or desktop tool, in the environment that tool needs. See [Pods](/dashboard/capsule/pods) for how sandboxes start and stop, and [Templates](/dashboard/capsule/templates) for the two environments.

## Calling the agent from your app

Your app authenticates with one of the agent's [API keys](/dashboard/api-keys), and the key already identifies the agent. `agent_name` on [`POST /v1/jobs`](/api-reference/chat/stream) is therefore optional; if you send it, it must be the agent's own name, and any other name returns `404`. [`GET /v1/agents`](/api-reference/agents/list) returns the one agent the key belongs to.

## Deleting an agent

Open **Settings** → **Agent settings** → **Danger zone**, or the agent's menu in the agent switcher, and type the agent's name to confirm. The dialog lists what will be removed.

Deleting an agent stops its running jobs and sandboxes and removes the agent together with everything that belongs to it. It can't be undone. Only the agent's creator or a team owner or admin can delete it.
