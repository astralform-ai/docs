## Overview

Client tools run on the iOS device and give the AI access to local capabilities. You register a handler with the session's tool registry; when the agent calls the tool, **the SDK runs your handler and submits the result for you** — there is nothing to catch and nothing to post.

Tool names must start with `mcp_` for the backend to route them.

## Registering a Tool

```swift
session.toolRegistry.registerTool(
    name: "mcp_get_calendar_events",
    description: "Read the user's calendar events for a given day.",
    inputSchema: [
        "type": .string("object"),
        "properties": .object([
            "date": .object([
                "type": .string("string"),
                "description": .string("ISO 8601 date, e.g. 2026-09-06"),
            ])
        ]),
        "required": .array([.string("date")]),
    ]
) { arguments in
    guard case .string(let date)? = arguments["date"] else {
        return "Missing required argument: date"
    }
    return await getCalendarEvents(on: date)
}
```

The handler is `([String: JSONValue]) async throws -> String` — return the result as a string and throw or return an error message if the tool fails. Either way the turn continues; see [Tool Result](/api-reference/chat/tool-result) for what the SDK posts on your behalf.

The registry is read on **every message**, not at connect time — the manifest is attached to each job request — so tools can be registered at any point, before or after `connect()`. `session.toggleClientTool(name:)` turns one on or off for the end user without unregistering it.

## Example: Calendar Tool

The registry dispatches by name, so each tool is just its handler — no central `switch`.

```swift
import EventKit

func getCalendarEvents(on date: String) async -> String {
    let store = EKEventStore()

    guard (try? await store.requestFullAccessToEvents()) == true else {
        return "Calendar access denied"
    }

    let iso = DateFormatter()
    iso.dateFormat = "yyyy-MM-dd"
    guard let day = iso.date(from: date) else {
        return "Could not parse date: \(date)"
    }

    let calendar = Calendar.current
    let start = calendar.startOfDay(for: day)
    let end = calendar.date(byAdding: .day, value: 1, to: start)!

    let predicate = store.predicateForEvents(withStart: start, end: end, calendars: nil)
    let events = store.events(matching: predicate)

    let formatted = events.map { event in
        "\(event.title ?? "Untitled"): \(event.startDate.formatted())"
    }.joined(separator: "\n")

    return formatted.isEmpty ? "No events on \(date)" : formatted
}
```

## Watching a Tool Run

Tool execution surfaces as an ordinary `tool_use` block, so a UI can show progress without participating in the call:

```swift
_ = session.on { event in
    switch event {
    case .blockStart(let block) where block.kind == .toolUse:
        print("running \(block.metadata)")
    case .blockStop(let block):
        print("finished \(block.path) status \(block.status)")
    default:
        break
    }
}
```

## Built-in Tool Schemas

Schemas you can copy. Each name carries the `mcp_` prefix the backend routes on; the calendar entry matches the handler registered above.

### Calendar Events
```json
{
  "name": "mcp_get_calendar_events",
  "description": "Read the user's calendar events for a given day.",
  "input_schema": {
    "type": "object",
    "properties": {
      "date": {"type": "string", "description": "ISO 8601 date, e.g. 2026-09-06"}
    },
    "required": ["date"]
  }
}
```

### Contacts
```json
{
  "name": "mcp_search_contacts",
  "description": "Search user's contacts by name",
  "input_schema": {
    "type": "object",
    "properties": {
      "query": {"type": "string"}
    },
    "required": ["query"]
  }
}
```

### Location
```json
{
  "name": "mcp_get_current_location",
  "description": "Get user's current GPS location",
  "input_schema": {
    "type": "object",
    "properties": {}
  }
}
```
