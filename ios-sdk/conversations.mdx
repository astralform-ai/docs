## Creating a Conversation

Start a new conversation:

```swift
let id = try await session.createNewConversation()
print("Created conversation: \(id)")
```

You rarely need this — `send` creates one on the first message when the session has none.

## Streaming Chat

Send a message and receive streaming responses:

Register a handler, then send. Events arrive on the session for as long as it is connected — including events from a turn started on another device.

```swift
_ = session.on { event in
    switch event {
    case .messageStart(let start):
        print("model: \(start.model)")

    case .blockDelta(_, .text(let text)):
        // Append text to your UI
        print(text, terminator: "")

    case .blockDelta(_, .thinking(let text)):
        print("[thinking] \(text)")

    case .blockStop(let block):
        print("closed \(block.path) status \(block.status)")

    case .messageStop(let stop):
        print("\n[Done] \(stop.stopReason)")

    default:
        break
    }
}

// The first message of a conversation names its model; later ones may omit it.
try await session.send(
    "What's the weather like today?",
    options: SendOptions(provider: "anthropic", model: "claude-sonnet-5")
)
```

`send` takes a `SendOptions` for everything about the turn besides its text:

| Field | What it sets |
|-------|--------------|
| `provider`, `model` | The model for this turn, always together. Required on a conversation's first message; omit both later to reuse the conversation's model. |
| `reasoningEffort`, `temperature` | How hard the model reasons, one rung of its ladder, and the sampling temperature (0–2). Omit either for the model's default. |
| `conversationId` | The conversation to send to. A new one is created when the session has none. |
| `uploadIds` | Uploaded attachments for this turn. |
| `enabledClientTools` | Which of the app's [client tools](/ios-sdk/client-tools) the end user has switched on. |
| `planMode`, `imageMode`, `videoMode` | The turn's mode, as on [`POST /v1/jobs`](/api-reference/chat/stream). |
| `goal` | Start a long-horizon goal and run this turn under it. |
| `agentName` | The agent's own name. Optional: the key already identifies the agent. |

`ChatStreamRequest` (via `session.client`, not `send`) additionally takes `harnessReleaseId` and `harnessConfiguration`: the Harness release and configuration for a **new** conversation, by release id — pinned immutably by the first turn. See [Harness selection](#harness-selection).

## Harness selection

Every conversation runs on one Harness release, pinned by its first turn. Pass the selection on `ChatStreamRequest` through the session's client — `SendOptions` carries no Harness fields, so `send` cannot name one:

```swift
let created: JobCreateResponse = try await session.client.post(
    "/v1/jobs",
    body: ChatStreamRequest(
        message: "What's the weather like today?",
        provider: "anthropic",
        model: "claude-sonnet-5",
        harnessReleaseId: "2578998f-f236-4edf-8721-8c7138db4e01",
        harnessConfiguration: ["mode": .string("edit")]
    )
)

// The admitted identity — what the conversation pinned, not what was asked.
print(created.harness?.releaseId as Any, created.harness?.profile as Any)
```

Offer the choice from [`GET /v1/me/harness-catalog`](/api-reference/chat/stream#harness-catalog), which lists the published releases this agent may actually admit with their `supported_features` and `is_default`. Naming a different release or configuration on a pinned conversation is refused with `409` — start a new conversation to switch. Omitted, the agent's default release applies (explicit, else the newest published `astralform` release); the configuration defaults the same way, and neither response ever echoes it back. Gate a mode on the release's declared `supported_features`, not on the profile name or the coarse `capabilities` — a turn needing an undeclared feature is refused before anything billable runs. No profile parity is promised: releases differ in which features they declare, and nothing here claims one profile's tools, skills, memory, continuation, or recovery behave like another's.

The admitted identity comes back on `JobCreateResponse.harness` and `JobStatus.harness` (`sessionId`, nullable `releaseId`, `profile`, `legacyNative`). A server from before Harness selection omits it — `harness` decodes as `nil`, and the selection fields are ignored. Read both absences as "unknown": a pre-selection conversation answers `legacyNative: true` with a `nil` release, and its historical release is never inferred from the profile.

## Event Types

`ChatEvent` mirrors the wire protocol one-for-one — see [Stream a Chat](/api-reference/chat/stream#the-block-protocol) for what each carries.

| Event | Description |
|-------|-------------|
| `messageStart(WireMessageStart)` | A turn begins; carries the model and the answering agent |
| `blockStart(WireBlockStart)` | A block opens — `text`, `thinking` or `tool_use` |
| `blockDelta(path:delta:)` | Incremental content; `delta` is `.text`, `.thinking`, `.input`, `.output`, … |
| `blockStop(WireBlockStop)` | A block closes with its terminal status and `final` content |
| `messageStop(WireMessageStop)` | The turn ends, with `stopReason` and token usage |
| `error(code:message:blockPath:)` | A fatal error ended the turn |
| `stall` / `retry` / `keepalive` | Reliability signals; the stream is still open |
| `todoUpdate`, `titleGenerated`, `toolApprovalRequested`, … | Conversation-level events |

The enum is non-exhaustive in practice, so always include a `default` case.

## Listing Conversations

Get all conversations:

```swift
_ = try await session.loadMoreConversations()

for conv in session.conversations {
    print("\(conv.id): \(conv.title) — \(conv.messageCount) messages")
}
```

`loadMoreConversations` appends the next page to `session.conversations` and returns what it added; `session.hasMoreConversations` says whether to keep going.

## Getting Conversation History

Retrieve messages from a conversation:

```swift
try await session.loadConversation(id: id)

for message in session.messages {
    print("[\(message.role)]: \(message.content)")
}
```

Older pages come from `session.loadOlderMessages()`, gated on `session.hasMoreMessages`.

## Deleting a Conversation

Remove a conversation and its messages:

```swift
try await session.deleteConversation(id: id)
```

## Renaming a Conversation

```swift
try await session.renameConversation(id: id, title: "Weather chat")
```

## SwiftUI Integration

`ChatSession` is `@MainActor` but not `@Observable`, so mirror what you render into `@State` from the event handler:

```swift
struct ChatView: View {
    let session: ChatSession

    @State private var transcript: [Message] = []
    @State private var streaming = ""
    @State private var input = ""
    @State private var isStreaming = false
    @State private var subscription: UUID?

    var body: some View {
        VStack {
            ScrollView {
                ForEach(transcript) { message in
                    Text(message.content)
                }
                if !streaming.isEmpty { Text(streaming) }
            }

            HStack {
                TextField("Message", text: $input)
                Button("Send") { Task { await send() } }
                    .disabled(isStreaming || input.isEmpty)
            }
            .padding()
        }
        .onAppear {
            guard subscription == nil else { return }
            subscription = session.on { event in
                switch event {
                case .blockDelta(_, .text(let text)):
                    streaming += text
                case .messageStop:
                    transcript = session.messages
                    streaming = ""
                default:
                    break
                }
            }
        }
        .onDisappear {
            if let subscription { session.unsubscribe(subscription) }
            subscription = nil
        }
    }

    private func send() async {
        let text = input
        input = ""
        isStreaming = true
        defer { isStreaming = false }
        do {
            try await session.send(
                text, options: SendOptions(provider: "anthropic", model: "claude-sonnet-5")
            )
            transcript = session.messages
        } catch {
            print("Error: \(error)")
        }
    }
}
```
